# المنصة الموحدة

منصة تجمع عدة أدوات تشغيلية ومالية داخل واجهة واحدة، مع:

- **قاعدة بيانات SQLite** حقيقية (بدون أي اعتماديات native خارجية — تستخدم وحدة `node:sqlite` المدمجة في Node.js).
- **بوابة دخول عامة** لكل المنصة (`/login.html`) بجلسات مبنية على JWT في كوكي `httpOnly`.
- **صلاحيات لكل مستخدم حسب كل تطبيق على حدة** — كل أداة من الأدوات السبع (الكاشير، CFO، مرجع F&B، الأسطول، عقود الإيجار، دليل التسعير، الاستراتيجية) لها معرّف مستقل، والمستخدم لا يرى أو يقدر يفتح إلا الأدوات المصرَّح له فيها.
- **لوحة إدارة** (`/admin.html`) لإنشاء المستخدمين، تفعيل/تعطيل الحسابات، إعادة تعيين كلمات المرور، ومنح/سحب صلاحية كل تطبيق لكل مستخدم — متاحة فقط لحساب "مدير المنصة" (super admin).
- التحقق من الصلاحية **يتم على السيرفر أيضاً** (وليس فقط بإخفاء الزر في الواجهة): مسار `/tools/:id` يرفض الطلب بـ 401/403 إذا لم يكن المستخدم مسجّل دخول أو ماله صلاحية على هذا التطبيق تحديداً.

## البنية

```
server/
  index.js          نقطة تشغيل السيرفر (Express)
  auth.js            توقيع/تحقق الجلسات + middleware الصلاحيات
  db/index.js        الاتصال بقاعدة البيانات وإنشاء الجداول
  db/seed.js          سكربت تعبئة أولية (تطبيقات + حساب مدير)
  routes/auth.js       تسجيل الدخول / الخروج / بيانات المستخدم الحالي
  routes/admin.js       إدارة المستخدمين والصلاحيات (super admin فقط)
  routes/tools.js        تقديم ملفات الأدوات بعد التحقق من الصلاحية
public/
  index.html          لوحة الأدوات (تجلب فقط الأدوات المصرَّح بها من الـ API)
  login.html           صفحة تسجيل الدخول
  admin.html            لوحة إدارة المستخدمين والصلاحيات
  tools/*.html           الأدوات السبع (كل واحدة ملف مستقل)
  assets/theme.css        التنسيق المشترك
data/                  قاعدة بيانات SQLite (تُنشأ تلقائياً، غير مرفوعة على git)
```

## التشغيل محلياً

```bash
npm install
cp .env.example .env
# عدّل JWT_SECRET وبيانات حساب المدير الأول داخل .env

npm start         # يشغّل السيرفر على http://localhost:3000 (يزرع قاعدة البيانات تلقائياً عند أول تشغيل)
```

بعدها افتح `http://localhost:3000`، وسيتم تحويلك تلقائياً لصفحة تسجيل الدخول. سجّل دخول بحساب المدير (`SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` من `.env`)، ثم غيّر كلمة المرور، وأنشئ باقي المستخدمين من لوحة الإدارة.

> السيرفر يستدعي سكربت الزرع (seed) تلقائياً عند كل إقلاع — وهو آمن التكرار (idempotent)، ما رح يكرر التطبيقات ولا يعيد إنشاء حساب المدير إذا كان موجود أصلاً. `npm run seed` لسا موجود لو حبيت تشغّله يدوياً.

## نشر المنصة على الإنترنت (رابط دخول عام حقيقي)

المنصة الآن تعمل محلياً فقط. عشان يصير عندك رابط دخول عام يشتغل بشكل دائم، لازم تستضيفها على خدمة استضافة — ما فيني أنا (Claude) أعمل هذا الجزء نيابةً عنك لأنه يحتاج حساب/بطاقة دفع خاصين فيك على منصة الاستضافة. جهّزت المشروع عشان يكون النشر بسيط:

يحتوي المشروع على `Dockerfile` جاهز، وقاعدة البيانات (SQLite) لازم تُخزَّن على **قرص دائم (persistent volume/disk)** حتى ما تنمسح البيانات عند كل إعادة نشر.

### الخيار المقترح: Railway (بسيط ويدعم Volumes)

1. أنشئ حساب على [railway.app](https://railway.app) واربطه بحساب GitHub تبعك.
2. اعمل **New Project → Deploy from GitHub repo** واختَر هذا المستودع (`accabdullahismail1991-lgtm/-Azie`) وفرع `main` بعد ما يتم الدمج.
3. Railway رح يكتشف الـ `Dockerfile` تلقائياً ويبنيه.
4. من إعدادات المشروع (Variables) ضيف:
   - `JWT_SECRET` (قيمة عشوائية طويلة)
   - `SEED_ADMIN_USERNAME`
   - `SEED_ADMIN_PASSWORD`
   - `NODE_ENV=production`
5. من تبويب **Volumes**، أضف Volume واربطه بمسار `/app/data` (نفس قيمة `DATA_DIR` في `Dockerfile`) حتى تبقى قاعدة البيانات محفوظة بين عمليات النشر.
6. بعد نجاح النشر، Railway بيعطيك رابط عام (`https://<اسم-مشروعك>.up.railway.app`) — هذا هو رابط الدخول العام للمنصة، وصفحة الدخول رح تكون على المسار الجذر مباشرة.

### بدائل أخرى

- **Fly.io**: يدعم Volumes بشكل مشابه، وله CLI (`fly launch`) يستخدم نفس الـ `Dockerfile`.
- **Render**: يدعم Docker، لكن الـ Persistent Disk متاح فقط على الخطط المدفوعة (الخطة المجانية تفقد البيانات عند كل إعادة تشغيل).
- **VPS خاص فيك** (مثل DigitalOcean/Hetzner): `docker build -t azie-platform . && docker run -d -p 3000:3000 --env-file .env -v $(pwd)/data:/app/data azie-platform`، وبعدها تحط دومين + شهادة SSL (مثلاً عبر Nginx + Let's Encrypt) قدّامه.

## إدارة الصلاحيات

من لوحة الإدارة (`/admin.html`):

1. أنشئ مستخدم جديد باسم مستخدم وكلمة مرور، واختَر مباشرة الأدوات اللي بدك تمنحه صلاحية عليها.
2. من جدول المستخدمين، اضغط على أيقونة أي تطبيق لتفعيل/إلغاء صلاحية ذلك المستخدم عليه فوراً (بدون حفظ إضافي).
3. حساب "مدير منصة" (`is_super_admin`) عنده صلاحية تلقائية على كل الأدوات الحالية والمستقبلية، ووحده يقدر يدخل لوحة الإدارة.

## ملاحظات أمنية

- كلمات المرور مخزّنة مُشفّرة بـ bcrypt (لا يوجد نص واضح أبداً في قاعدة البيانات).
- الجلسة عبارة عن JWT موقّع بمفتاح سري (`JWT_SECRET`) داخل كوكي `httpOnly` + `SameSite=Lax`، ويُفعَّل `Secure` تلقائياً عند `NODE_ENV=production` (يتطلب HTTPS).
- التحقق من صلاحية كل تطبيق يحدث على مستوى السيرفر (مسار `/tools/:id`)، فحتى لو تم التلاعب بواجهة المستخدم، السيرفر يرفض تقديم ملف الأداة لأي مستخدم غير مصرَّح له.
- غيّر قيمة `JWT_SECRET` وكلمة مرور حساب المدير الافتراضية قبل أي استخدام حقيقي/إنتاجي.
