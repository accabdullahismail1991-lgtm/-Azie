# المنصة الموحدة

منصة تجمع عدة أدوات تشغيلية ومالية داخل واجهة واحدة، مع:

- **قاعدة بيانات PostgreSQL حقيقية** عبر الشبكة (تدعم أي مزوّد مجاني مثل Neon أو Supabase، أو Postgres محلي/خاص فيك) — تُضبط بالكامل عبر متغير بيئة واحد `DATABASE_URL`.
- **بوابة دخول عامة** لكل المنصة (`/login.html`) بجلسات مبنية على JWT في كوكي `httpOnly`.
- **صلاحيات لكل مستخدم حسب كل تطبيق على حدة** — كل أداة من الأدوات السبع (الكاشير، CFO، مرجع F&B، الأسطول، عقود الإيجار، دليل التسعير، الاستراتيجية) لها معرّف مستقل، والمستخدم لا يرى أو يقدر يفتح إلا الأدوات المصرَّح له فيها.
- **لوحة إدارة** (`/admin.html`) لإنشاء المستخدمين، تفعيل/تعطيل الحسابات، إعادة تعيين كلمات المرور، ومنح/سحب صلاحية كل تطبيق لكل مستخدم — متاحة فقط لحساب "مدير المنصة" (super admin).
- التحقق من الصلاحية **يتم على السيرفر أيضاً** (وليس فقط بإخفاء الزر بالواجهة): مسار `/tools/:id` يرفض الطلب بـ 401/403 إذا لم يكن المستخدم مسجّل دخول أو ماله صلاحية على هذا التطبيق تحديداً.

## البنية

```
server/
  index.js          نقطة تشغيل السيرفر (Express) — يجهّز قاعدة البيانات (schema + seed) قبل الاستماع
  auth.js            توقيع/تحقق الجلسات + middleware الصلاحيات
  db/index.js        اتصال pg Pool بقاعدة البيانات + تعريف الجداول (schema)
  db/seed.js          سكربت تعبئة أولية (تطبيقات + حساب مدير) — آمن التكرار (idempotent)
  routes/auth.js       تسجيل الدخول / الخروج / بيانات المستخدم الحالي
  routes/admin.js       إدارة المستخدمين والصلاحيات (super admin فقط)
  routes/tools.js        تقديم ملفات الأدوات بعد التحقق من الصلاحية
public/
  index.html          لوحة الأدوات (تجلب فقط الأدوات المصرَّح بها من الـ API)
  login.html           صفحة تسجيل الدخول
  admin.html            لوحة إدارة المستخدمين والصلاحيات
  tools/*.html           الأدوات السبع (كل واحدة ملف مستقل)
  assets/theme.css        التنسيق المشترك
```

## التشغيل محلياً

### 1. جهّز قاعدة بيانات Postgres

أسهل طريقة (بدون تنصيب أي شيء): أنشئ قاعدة بيانات مجانية على **[Neon](https://neon.tech)** (لا تحتاج بطاقة ائتمان) — خذ رابط الاتصال (Connection String) اللي بيعطيكياه، شكله يكون تقريباً:

```
postgresql://user:password@ep-xxxx.aws.neon.tech/dbname?sslmode=require
```

أو إذا عندك Postgres محلي/خاص فيك، استخدم رابط الاتصال الخاص فيه مباشرة.

### 2. اضبط متغيرات البيئة

```bash
npm install
cp .env.example .env
# افتح .env وحط:
#   DATABASE_URL=<رابط الاتصال اللي أخذته من الخطوة السابقة>
#   JWT_SECRET=<قيمة عشوائية طويلة>
#   SEED_ADMIN_USERNAME / SEED_ADMIN_PASSWORD حسب ما تحب
```

### 3. شغّل المنصة

```bash
npm start   # يجهّز الجداول تلقائياً (schema + seed) عند أول تشغيل، ثم يشغّل السيرفر على http://localhost:3000
```

> السيرفر يستدعي سكربت الزرع (seed) تلقائياً عند كل إقلاع — وهو آمن التكرار، ما رح يكرر التطبيقات ولا يعيد إنشاء حساب المدير إذا كان موجود أصلاً. `npm run seed` لسا موجود لو حبيت تشغّله يدوياً بمعزل عن تشغيل السيرفر.

بعدها افتح `http://localhost:3000`، وسيتم تحويلك تلقائياً لصفحة تسجيل الدخول. سجّل دخول بحساب المدير (`SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` من `.env`)، ثم غيّر كلمة المرور، وأنشئ باقي المستخدمين من لوحة الإدارة.

## نشر المنصة مجاناً على الإنترنت (رابط دخول عام حقيقي)

ما فيني أنا (Claude) أنشئ لك حسابات على خدمات الاستضافة نيابةً عنك — بيحتاج بريدك وربطها بحسابك. لكن المشروع جاهز بالكامل للنشر بأقل خطوات ممكنة، وبدون أي بطاقة ائتمان، باستخدام مزوّدَين مجانيين:

### قاعدة البيانات: Neon (PostgreSQL مجاني ودائم)

1. سجّل حساب على [neon.tech](https://neon.tech) (بريد إلكتروني فقط، بدون بطاقة).
2. أنشئ مشروع جديد → خذ رابط الاتصال (Connection String) — هذا هو قيمة `DATABASE_URL`.
3. الخطة المجانية دائمة (لا تنتهي بعد 90 يوم مثل بعض المزوّدين)، بحد تخزين ~0.5GB يكفي لهذا الاستخدام بشكل مريح.

### السيرفر: Render (خدمة ويب مجانية)

1. أنشئ حساب على [render.com](https://render.com) واربطه بحساب GitHub تبعك.
2. **New → Web Service** واختَر هذا المستودع (`accabdullahismail1991-lgtm/-Azie`) وفرع `main` (بعد دمج الـPR).
3. Render رح يكتشف الـ `Dockerfile` تلقائياً (أو اختَر Environment: Docker يدوياً).
4. من **Environment Variables** ضيف:
   - `DATABASE_URL` (رابط Neon من الخطوة السابقة)
   - `JWT_SECRET` (قيمة عشوائية طويلة)
   - `SEED_ADMIN_USERNAME`
   - `SEED_ADMIN_PASSWORD`
   - `NODE_ENV=production`
5. اضغط Deploy. بعد نجاح النشر، Render بيعطيك رابط عام (`https://<اسم-خدمتك>.onrender.com`) — هذا هو رابط الدخول العام للمنصة (صفحة الدخول على المسار الجذر مباشرة).

> ملاحظة: الخطة المجانية على Render "تنام" الخدمة بعد ~15 دقيقة بدون طلبات، وأول طلب بعدها بياخد بضع ثواني لإيقاظها — هذا طبيعي على الخطط المجانية ومالوش علاقة بقاعدة البيانات (البيانات محفوظة دايماً على Neon بشكل منفصل ومستقل عن حالة السيرفر).

### بدائل أخرى

- **قاعدة بيانات**: Supabase (Postgres مجاني) بدل Neon.
- **سيرفر**: Railway أو Fly.io بدل Render — نفس الفكرة (Dockerfile جاهز، فقط ضيف متغيرات البيئة نفسها).
- **VPS خاص فيك**: `docker build -t azie-platform . && docker run -d -p 3000:3000 --env-file .env azie-platform`، وبعدها حط دومين + شهادة SSL (مثلاً عبر Nginx + Let's Encrypt) قدّامه.

## إدارة الصلاحيات

من لوحة الإدارة (`/admin.html`):

1. أنشئ مستخدم جديد باسم مستخدم وكلمة مرور، واختَر مباشرة الأدوات اللي بدك تمنحه صلاحية عليها.
2. من جدول المستخدمين، اضغط على أيقونة أي تطبيق لتفعيل/إلغاء صلاحية ذلك المستخدم عليه فوراً (بدون حفظ إضافي).
3. حساب "مدير منصة" (`is_super_admin`) عنده صلاحية تلقائية على كل الأدوات الحالية والمستقبلية، ووحده يقدر يدخل لوحة الإدارة.

## ملاحظات أمنية

- كلمات المرور مخزّنة مُشفّرة بـ bcrypt (لا يوجد نص واضح أبداً في قاعدة البيانات).
- الجلسة عبارة عن JWT موقّع بمفتاح سري (`JWT_SECRET`) داخل كوكي `httpOnly` + `SameSite=Lax`، ويُفعَّل `Secure` تلقائياً عند `NODE_ENV=production` (يتطلب HTTPS).
- الاتصال بقاعدة البيانات يستخدم TLS تلقائياً مع المزوّدين المُدارين (Neon/Supabase/Render) عبر `sslmode=require` في رابط الاتصال.
- التحقق من صلاحية كل تطبيق يحدث على مستوى السيرفر (مسار `/tools/:id`)، فحتى لو تم التلاعب بواجهة المستخدم، السيرفر يرفض تقديم ملف الأداة لأي مستخدم غير مصرَّح له.
- غيّر قيمة `JWT_SECRET` وكلمة مرور حساب المدير الافتراضية قبل أي استخدام حقيقي/إنتاجي.
